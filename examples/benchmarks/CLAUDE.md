# CLAUDE.md — benchmarks demo project

## What this project is

This is the agentbox build-flow demo. It exists so you (the agent) can
demonstrate the full Task-Runner round-trip end-to-end: you write a
task file, the host-side runner validates and executes `build.ps1`,
the build measures 5 host workloads, and the result lands back as
`bench-results.jsonl` + a generated `index.html` in the project root
plus a status JSON in `_tasks/`.

Don't edit `project.json` — it's read-only for you (per
`/workspace/SYSTEM_META_PROMPT.md`). The build command is already
wired: `powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1`.

## Optional: prime the Sandbox side first

`build.ps1` produces a Host-measurement. If you also want the
Wirkungsgrad comparison (host vs. sandbox) in the generated
`index.html`, run the sandbox-side script once before triggering the
build:

```bash
bash /workspace/_control/tools/bench.sh  # if _control is mounted
# OR, if you have a local copy:
bash _control/tools/bench.sh
```

That appends one `platform: "sandbox"` line to `bench-results.jsonl`.
The subsequent `build.ps1` will include it in the averaged table.

This step is optional — the demo works with host-only numbers too.

## How to trigger a build (exact steps)

Write the task file as `.tmp` first, then rename — the runner only
picks up `.json` files, so the rename guarantees atomicity:

```bash
cat > /workspace/_tasks/build_001.tmp << 'EOF'
{
  "project": "benchmarks",
  "action": "build",
  "timestamp": "2026-04-18T14:30:00"
}
EOF

mv /workspace/_tasks/build_001.tmp /workspace/_tasks/build_001.json
```

Then poll `/workspace/_tasks/status_build.json` until `status` is
`done` or `failed`:

```bash
while [ ! -f /workspace/_tasks/status_build.json ] || \
      grep -q '"status": "running"' /workspace/_tasks/status_build.json; do
    sleep 1
done
cat /workspace/_tasks/status_build.json
```

## What you'll see after a successful build

- **`bench-results.jsonl`** — one new line appended with your host
  run. Each line is a compact JSON object with `timestamp`,
  `platform`, `version`, `net_mbs`, `disk_seq_mbs`,
  `disk_small_files_per_s`, `cpu_sha256_mbs`, `proc_spawn_per_s`.
- **`index.html`** — freshly regenerated by `bench.ps1` at the end
  of the build. Shows averages over all host and sandbox runs plus a
  traffic-light Wirkungsgrad column (green ≥100 %, yellow ≥50 %, red
  below). Open it locally to see the demo output rendered.
- **`_tasks/status_build.json`** — `{ "status": "done", ... }`.

## Why this demo matters

- Shows the **build command doesn't execute in the sandbox** — it
  runs on the Windows host via `cmd.exe /c`. That's why
  `bench.ps1` can measure real NTFS disk-write speed, host-side
  HTTPS download throughput, native CPU SHA256, and Windows process
  spawn — none of which you can measure from inside the sandbox.
- Shows the **exact-match whitelist**: if someone tampers with
  `build.command` in `project.json` (they can't, it's read-only, but
  hypothetically), the runner rejects it before execution.
- Shows that **the agent never touches PowerShell** — you only write
  a 3-line JSON file; everything else is plumbed.
- Shows the **build-step-generates-artifact** pattern: the build
  doesn't just compile code, it produces a human-viewable output
  (`index.html`) that can be opened directly.

## If the build fails

Read `_tasks/status_build.json` for the `error` field. Common causes:

- `_control/tools/bench.ps1` missing → user hasn't pulled a recent
  agentbox version. `build.ps1` falls back to a no-op "demo build
  completed" message in that case, so status should still be `done`.
- Whitelist mismatch → shouldn't happen in this demo; means someone
  changed `project.json:build.command` away from the canonical form.
- Network tests time out → agentbox sandbox allows HTTPS to public
  IPs, but the bench uses `cachefly.cachefly.net` / `proof.ovh.net` /
  `speed.cloudflare.com` — if all three are blocked by an upstream
  SNI-filter, `net_mbs` will be `0` in the JSONL. Set
  `$env:BENCH_URL` on the host to a reachable 100 MB URL to override.
